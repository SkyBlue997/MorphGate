# v0.1.0-preview.1 — Phase 1 source preview

Defensive bot-management and traffic-security platform for owner-controlled web properties.

This is the first source preview of MorphGate's Phase 1 implementation. It is intended for local evaluation and owner-operated staging deployments. Follow the [getting-started guide](../getting-started.md) to build the Edge, operations CLI, Validation Lab and browser SDK, and run the loopback checks.

## Included

- Rust/Pingora Edge with request trust checks, risk scoring, policy enforcement, rate limiting, crawler verification and origin proxying.
- Owner-signed configuration bundles, sealed proof-of-work challenges, short-lived clearance tokens and replay-state handling.
- Go `mgctl` for key management, policy/bundle operations, audit verification, Cloudflare configuration auditing and intelligence synchronization.
- A first-party browser SDK and challenge-page template, plus allowlisted loopback validation scenarios.
- Apache-2.0 licensing for the project's own code, named security-maintainer documentation and a private vulnerability-reporting policy.

## Distribution and build

The release tag is `v0.1.0-preview.1`. GitHub's source archives contain the repository at that tag. There are no prebuilt native binaries or bundled third-party dependencies in this preview. Build with the committed Rust and pnpm lockfiles and Go module checksums; the [guide](../getting-started.md) lists prerequisites and exact commands.

The repository has local macOS arm64 validation and Ubuntu 24.04 x86_64 CI coverage. Other platforms are unverified. Existing component version strings are unchanged: Edge `0.1.0`, SDK `0.1.0-phase1`.

The source includes intentionally public test credentials, TLS test private keys, fixture SDK files and synthetic intelligence data so tests remain reproducible. They are test inputs only. Generate fresh deployment keys with `mgctl` and build the SDK from source; never deploy those fixtures as live credentials or browser assets.

## Preview limitations

- The real Cloudflare monitor period of at least seven days, owner-zone audit, browser regression checks and production p99 latency acceptance are pending. Loopback tests do not establish those results.
- `mg-control` exposes health checking and a placeholder bundle endpoint. The complete control-plane management API/UI is not implemented.
- Interactive challenges, later SDK telemetry/session features and full AI-agent governance are future phases. Phase 1 challenge execution uses proof of work.
- The systemd configuration and development Compose file are examples requiring operator configuration. The development defaults and public test keys are unsuitable as deployment secrets.
- No external adoption figures, production-readiness certification or program eligibility are asserted by this release. Release publication alone does not demonstrate third-party adoption.

For detailed implementation boundaries and open acceptance items, see [Phase 1 status](../impl/phase1-status.md). Before deploying or upgrading, follow the configuration and credential procedure in the [getting-started guide](../getting-started.md) and the [control-plane reference](../../control-plane/README.md).
