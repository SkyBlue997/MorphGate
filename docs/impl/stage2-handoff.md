An existing log's bytes stay unchanged, and a missing log becomes a valid empty one. New tests audit/TestOpenFailsWhenTheLogIsNotWritable and mgctl/TestReadOnlyAuditLogFailsBeforeAnyWrite both failed before the fix: the syncs sent requests and wrote files.

- [WP-C4] (medium) Design coupling, not fixed (the spec prescribes it; needs an integrator decision). One flusher sends each batch to VictoriaLogs, the file and mg:ev together, and the next batch starts only after all outputs finish (edge-core/src/events/queue.rs Flusher::run / deliver). A VictoriaLogs outage therefore throttles the healthy file sink and the mg:ev stream too. If VL hangs, each batch takes about 26.2 s (4 attempts x 5 s + 6.2 s backoff) for at most 1000 records, about 38 records/s. If VL refuses connections, each batch takes 6.2 s, about 160 records/s. Beyond that the class queues overflow and mg:ev entries and file lines are dropped as sink="buffer". Spec §9.11 says 'the same flusher' writes the stream, and the implementer documented the coupling. The integrator should decide whether VL delivery should be decoupled (e.g. a per-sink in-flight task with a bounded backlog). Impact in Phase 1 is limited: mg:ev has no consumer yet, and the file sink is for tests and the Lab.
- [WP-C4] (low) Spec gap, not fixed: vl_main / vl_short accept http:// to any host (endpoint_url only checks scheme, host, no userinfo, no query or fragment). Suggest the spec add the same rule for vl_*. Not changed because the spec does not require it.

- [WP-C4] (low) Hardening note, not fixed: the telemetry output bounds strings and arrays, but number() in telemetry.rs copies serde_json::Number as-is.
